# Hackathon Aprova 2026 — Agent Rules

1. Build the smallest reliable demo that clearly proves user value.
2. Prefer a working end-to-end flow over extra features or architecture.
3. Do not expand scope unless the expected judging value clearly justifies the time.
4. Treat product decisions, current implementation, and tested behavior as different facts.
5. If they diverge, report the divergence clearly.
6. When STATE.md exists, keep it brief and update it after material decisions, scope changes, proven milestones, blockers, or handoffs.
7. Do not read or write Pietro Brain / Obsidian unless explicitly requested.
8. Never claim something works until it has been verified by command, test, or demo.
9. Before risky changes near the demo, preserve or identify the last known-good state.
10. Deadline is hard: repository must be delivered by 17:00.
11. Aim to freeze feature development before 16:00 so README, INSTRUCTIONS, demo backup, Git and final verification can be completed safely.
12. The hackathon requires an agentic solution. Agent behavior must be explicit, inspectable and tied to real product actions.
13. The /INSTRUCTIONS folder is part of the judged deliverable. Keep agent responsibilities understandable to a judge.
14. Never fabricate integrations, metrics, customer data, or production behavior. Clearly identify simulated/demo data.
15. Do not commit secrets, API keys, .env files, credentials or personal data.
16. Do not commit or deploy unless Pietro explicitly authorizes it.
